# Local file facts

`inspect` reads only the local regular file selected by its caller. Use a worker thread. It binds the snapshot to the selected absolute DOS path, volume/file ID, size, modification time and caller generation. An expected binding rejects stale requests. SHA-256 is streamed in 64 KiB chunks with a byte limit and cooperative cancellation/time checks. Hash and child-wait budgets are capped at 30 seconds. File and directory handles are retained without delete sharing; file write sharing is denied during inspection. This is observation, not content pinning after return.

The module rejects UNC, remote drives, ADS, reparse points, directories, offline files and paths with ambiguous components. It does not enumerate processes, execute the selected file, transmit data, grant permissions or change firewall decisions. Identity and hash do not establish application legitimacy or absence of malware. The caller must discard late results whose generation is no longer current.

`WindowsSignatureBackend` retains the broker's original admitted `Deployment`. It obtains the fixed product helper from that deployment's retained GBD1 inventory, checks the opened helper's identity and SHA-256, and revalidates the deployment before launch and before accepting a result. A missing or revoked deployment leaves the signature unavailable. The helper uses a static runtime, inherits only a selected read handle and an anonymous response mapping, runs in a private Job with one process and kill-on-close, receives a minimal Unicode environment and loads WinTrust/Crypt32 from System32. It never receives the inspected file's path in its command line or executes the inspected file. The helper's verification phase has a bounded wait and cancellation; filesystem opening and hashing are cooperative and can block in operating-system I/O. This is not a general sandbox or administrator-resistant integrity guarantee.

Authenticode verification is embedded-signature only, `WTD_UI_NONE` and cache-only URL retrieval, with revocation checks disabled. `VerifiedOffline` means that this policy accepted the embedded signature using local state. It does not mean current revocation was checked, a catalog signature was evaluated, the software is safe or its public product name matches its certificate. Unavailable local trust/cache remains `Unavailable`. `publisherLocal` is bounded text taken from the accepted certificate, kept separately from any public name; it is untrusted display data and is never automatically included in public queries or external payloads.

Build this directory independently, or add it as a subdirectory. Production linking of the Windows backend also requires `gatebouncer_native_ii`, supplied by the root product build. No installer, service registration or runtime launch is part of the build. `SignatureBackend` is the test seam; production supplies the Windows backend with the original admitted broker deployment.

The original `GateBouncerAssistant.exe` also accepts `--inspect-offline <absolute-local-file>` without opening the service, assistance configuration or network transport. It requires its current ordinary process/token identity and the same protected broker deployment and helper inventory. An assembled source folder without the admitted GBD1 and protections is rejected. Optional `--hash-ms`, `--signature-ms` and `--cancel-after-ms` values range from 0 to 30,000; the default hashing and signature budgets are 5,000 and 3,000 milliseconds. These budgets do not impose a hard deadline on operating-system file I/O or deployment admission.

This entry writes one bounded JSON result to its caller's standard output: admission, inspection and signature states, native signature status, selected file size and SHA-256, and whether a publisher name is available. It omits paths, file IDs, account identity, certificate text and file content. A cancellation or changed owner clears the snapshot. The result is informational only and cannot grant network access or certify that a file is safe.
